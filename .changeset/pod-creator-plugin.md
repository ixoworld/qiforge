POD Creator plugin and `ctx.kv`, durable per-user plugin state.

- **POD Creator** (`pod-creator`, bundled, on-demand, experimental). Designs an IXO Programmable Organisational Domain through twelve stage-gated specialist sub-agents (qualify → architect → build → evaluate → package → gate), with conductor tools `start_pod_design`, `get_blueprint`, `compute_readiness` and `assemble_blueprint`. Once the launch gate passes, the create path prepares an UNSIGNED transaction batch through an injected `ChainGateway`, binds the user's approval to that exact batch, spends the approval on one `sign_transaction` request to the user's wallet over the realtime channel, and confirms the created POD. Approval is refused in the turn that prepared the batch, the launch gate is re-checked before the signature request, and restarting a design discards its prepared batch. The oracle never signs. The bundled instance has no chain gateway, so it reports on-chain creation as unavailable. No specialists are built before a design is opened, so the plugin costs one local read per turn for users who never use it. Specialists run on built-in prompts unless a fork passes `createRegistryInstructionsFetcher()`, which reads `GET /skills/{name}/instructions` from the capsules registry (64 KB cap, failures cached for 5 minutes). Keep it off until the `design-pod-*` registry names are owned: whoever publishes under them controls the specialist prompts.
- **Mainnet opt-in.** `POD_CREATOR_ALLOW_MAINNET` (default `false`) must be `'true'` before a mainnet batch is prepared or sent for signing. `NETWORK` defaults to `mainnet`, so an oracle that sets neither gets a refusal.
- **`ctx.kv`.** New optional `RuntimeContext` surface (`UserKvSurface`): JSON rows by namespace in the user's own SQLite file (`user_kv` table). The rows travel with the owner copy, so they survive eviction and a cold start. They support an idle TTL, a per-namespace LRU cap and an atomic `update`. The Workers host always provides it; an in-memory implementation for tests sits in `src/core/user-kv.ts`.
