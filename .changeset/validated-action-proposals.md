Add an opt-in durable action proposal contract and owner lifecycle for conversational token transfers. Bind Portal consent to immutable values, deliver friendly channel action links and scoped verified outcomes, and reuse one canonical Decision-subject hashing implementation across browser and Workers consumers.

The card's id is the transaction memo (`inputs.memo`, required by the contract) and chain verification accepts no other memo, so one signed transaction confirms exactly one card; a hash is recorded for one card per owner. The owner object enforces the card policy itself (owner, signer, non-mainnet, configured chain id, 15-minute expiry) and refuses cards asked for in group rooms. Evidence checks match whole addresses, amounts with their unit and whole token ids, and ignore the turn-time note. Unconfirmed transactions are re-verified from the alarm with a doubling cooldown, receipts back off and are abandoned or quarantined instead of retrying for ever, finished cards are pruned after 90 days, and the action-card settings are validated at boot. `MsgSend` joins the shared message catalogue.

Topic cards (`ACTION_TOPIC_PROPOSALS_ENABLED`, v2 contract): discussion drafts and claim-access grants run as step journals with one-use permits. The switch gates claims and permits, not reads. The card expiry bounds the first step only and an hour-long execution window after the claim bounds the rest; a started step with no reference is re-permitted to the same executor; a second grant for the same account while one is in flight is refused; a grant is merged into an existing authorization only under its existing expiry; authority fingerprints cover the contract head, the pinned body and room policy, not thread activity; changed authority answers 409 and an unavailable read 503; grant reads run in parallel. `@ixo/ixo-transaction` no longer bundles the chain SDK (peer dependency). The runtime requires a `@ixo/topic-protocol` build with precompiled validators (1.0.0-rc.8 or later); `src/core/topic-protocol-runtime.test.ts` fails the suite on a build that would generate code on Workers.
