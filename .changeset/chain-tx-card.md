Chain-transaction action cards: `request_chain_transaction` prepares one `ixo.chain.tx.v1` review in Auth Hub of 1 to 8 messages executed as one transaction (`cosmos.bank.send`, `ixo.claims.submit`, `ixo.claims.evaluate`, `ixo.token.transfer`; all succeed or none do). The model gives only the messages and an optional memo; the runtime adds the chain id, the account's network, the owner's address as signer and the owner's identity in claims messages (`agentDid` = `did:ixo:<signer>`, an evaluation's `agentAddress` = the signer: the evaluator, never the claimant), and Auth Hub sets the fee. The model cannot supply `agentDid` or `agentAddress` at all.

Discover, then request: the new read-only `describe_chain_messages` tool (`{types}`, 1 to 8 distinct types) returns each requested type's full rules (purpose, every field with its meaning, format and limits as JSON Schema, what the runtime fills, chain caveats), the rules all types share, and `availableTypes` (the catalogue filtered by the account's `chainTx.messageTypes`; the whole catalogue when the capabilities cannot be read). `request_chain_transaction`'s description is a few sentences plus one summary line per type, and its schema is constant in size (`messages: [{type, ...}]`, `memo`), so the per-request cost no longer grows with the catalogue: about 2.4 KB for both tools against about 7.6 KB before (the per-type schema and description plus the removed send tool); a new type adds one summary line and one enum value. The catalogue is one structure (`CHAIN_TX_CATALOG`: summary, rules and a strict zod schema per type). The handler checks each message strictly against its type (20-byte `ixo1…` addresses, ids in `[A-Za-z0-9:._/-]`, proofs up to 300 characters, `%xx` DID escapes, collection ids without leading zeros, a memo without control, invisible or text-direction characters, no field a type does not have) and refuses before any Hub call, naming each field (`messages[1].toAddress: …`); on a model turn LangChain still refuses the batch shape, unknown types and the memo with zod's paths first.

BREAKING for prompts and plugins: `request_hub_transfer` is removed, and so is the host's `ctx.hubActions.transfer`. A coin send, single or in a batch, is a `cosmos.bank.send` message of `request_chain_transaction` with a display `amount` (`"1.5"`) and an optional `denom` from `hub_action_options` `transfer.tokens` (default uixo). With at least one bank step the owner object reads the owner's options once per call, fresh (protocol version 4), refuses a token not in the list, more digits than its decimals, zero, and bank steps of one token above its listed balance together, converts with exact integer arithmetic and sends the protocol's `amountBaseUnits`; a transaction without a bank step reads no options. Auth Hub lists the tokens while `ixo.bank.send.v1` or `ixo.chain.tx.v1` is enabled for the account (Auth Hub PR 84); without a token list a bank step is refused. `request_hub_action` refuses `ixo.bank.send.v1` and `ixo.chain.tx.v1` with a pointer to `request_chain_transaction`. Auth Hub still serves the older `ixo.bank.send.v1` card for older runtimes; this runtime no longer prepares it but still reads such a card's outcome (`hub_action_status` summary line, the 0.4.1 receipt shape on channel polls). A chain-transaction review is now a Reply Plan `hub-action` card on chat surfaces like any other Hub review.

Auth Hub's prepare refusals (`operation_not_registered` with the field it refused, `not_authorized`, `insufficient_funds`, `fee_above_ceiling`, `simulation_failed`) reach the model in plain words; refusals the model cannot fix (`kind_disabled`, `invalid_operation: signer|network|chainId`, `protocol_version_required`, `invalid_request`, 404, the runtime's own "Invalid signer") say retrying or changing the fields will not help, and a 429 says to try again later. A chain-transaction prepare has a 15 s timeout (Auth Hub answers a slow chain with 503 at about 8 s). `hub_action_capabilities` returns the Hub's `chainTx` entry; outcomes with the new receipt (`steps`) are stored and relayed to the gateway unchanged. The runtime declares protocol version 4 on every Hub call and depends on `@ixo/action-protocol` 0.6.0. `prepublishOnly` now also refuses a `file:` dependency of the package being published.

Deploy order: Auth Hub (accepts version 4) → channel gateways on `@ixo/action-protocol` 0.6.0 → runtimes.
