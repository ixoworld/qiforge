Bundled-plugin hardening (VFS, sandbox, user preferences, editor).

- **VFS paths resolve exactly.** `vfs_share`, `vfs_delete`, `vfs_edit`, `vfs_move`, `vfs_write` (overwrite), `vfs_read` and `vfs_to_sandbox` act only on the file whose path equals the one given. `*` and `?` are no longer wildcards there: a pattern that matches other files resolves to nothing, a real file whose name contains `*` or `?` still resolves, and a path that matches two files is refused. `vfs_share` refuses a wildcard path that is not a file instead of publishing it as a folder.
- **Wildcard-character file names page through matches.** Resolving a file whose name contains `*` or `?` reads its pattern's matches in 200-entry pages until the file or a short page, up to 5,000 matches; past that the path is refused rather than reported missing.
- **`vfs_move` and `vfs_delete` take files only.** Their descriptions and their not-found replies now say so and point at `vfs_glob` for a folder's files (they never worked on folders).
- **`vfs_delete` is bounded.** At most 50 paths per call (was 1,000), looked up 6 at a time, with repeated paths looked up once.
- **VFS size caps.** `vfs_read` returns a metadata stub without downloading an image or document larger than 10 MB, or a binary type it would not render; downloads stop at the cap even when the stored size is wrong. `vfs_to_sandbox` refuses files over 10 MB before downloading.
- **VFS request timeout covers the body.** `VFS_REQUEST_TIMEOUT_MS` and turn cancellation now apply until the response body has been read, not only until the headers arrive.
- **Sandbox bridge.** `sandbox_to_vfs` / `vfs_to_sandbox` no longer hand the MCP client a tool timeout (which kept the user's Durable Object resident after `close()`); each call is bounded by its own 180 s timer that closes the client on expiry. `sandbox_to_vfs` checks the file size inside the sandbox and refuses files over 10 MB before encoding them. `vfs_to_sandbox` always sends bytes as base64, so text files in encodings other than UTF-8 arrive byte for byte.
- **MCP call timeouts reach the MCP request.** Sandbox (180 s), Memory Engine (420 s) and Firecrawl (120 s) tool calls pass their timeout to the MCP SDK as the request's own timeout (`metadata.timeoutMs`), which the SDK clears when the response arrives; without it every call was cut at the SDK's 60 s default.
- **`sandbox_write_blob`** reports `success: false` when the sandbox returns a failed write instead of throwing, and `bytesWritten` counts UTF-8 bytes.
- **User preferences.** `set_user_preferences` no longer overwrites the stored preferences when they could not be read (a gateway failure now fails the call; a missing event still writes). `tone` is limited to 120 characters on write, and a longer stored tone is cut to 120 characters when read, so it cannot inflate every prompt.
- **Editor.** `delete_block` and `move_block` refuse a `secrets` or `skills` block, or a block with one nested inside it (`prop_not_editable`). One `call_editor_agent` run opens its document once, on the first content-tool call, and closes it when the run ends, succeeds, fails or is cancelled (each tool call used to reopen it). The inner agent receives the turn's abort signal, so cancelling a turn stops its model calls and writes. The editor's Matrix client is rebuilt when the gateway hands out a different access token or homeserver, so edits stop failing with 401 after the gateway re-mints its device token. An editor write's outcome now comes from the provider's bounded flush: a write the homeserver forbids is still `needs_access`, while one that could not be delivered (server errors until the retry budget runs out, or an oversized change) is the new `write_not_saved` failure when it may still have landed, and an `error` that says nothing was stored when the homeserver refused it outright (413, 401, 400) (the `flush_timeout` code is gone), and later writes in the same run return the same failure without sending.
- **`ctx.secrets.getAll()`** (plugin API, additive): the values of every secret `getIndex` lists, from one read of the room's secret index. The sandbox uses it, so a sandbox connect reads room state once instead of twice; BYO credentials are likewise read with one room-state read. `SecretsAdapter.getAll` is optional; an adapter without it is served by `getIndex` + `getValues`. `ByoSecretsBackend` gains an optional `getValuesFor(roomId, entries)` (implemented by `WorkersSecretsService`); a backend without it keeps working through `getValues`.
- **Composio tool calls are bounded.** Each call gives up after 190 s and stops waiting as soon as the turn is cancelled; the SDK's own 60 s-per-attempt timeout stops at the response headers, so a stalled body used to be waited on forever.
