The POD Creator signs through the ixo-transaction `sign_transaction` contract, so one Portal handler (`useIxoTransactionSigningAction` from `@ixo/ixo-transaction/react`) serves both wallet-signing plugins.

- **`ChainGateway` (breaking for gateway authors).** `prepareUnsignedPodBatch` → `preparePodBatch`, returning `{ messages, summary, estimatedCost? }`: proto-JSON messages, never encoded bytes (`messageCount` is gone; it is the number of messages). Both methods take `network` as `'devnet' | 'testnet' | 'mainnet'`. `prepare_pod_transaction` validates every message against the `@ixo/ixo-transaction` catalog and refuses a batch that is not a POD batch (`POD_BATCH_TYPE_URLS`: `MsgCreateEntity` first and once, then entity accounts, claim collections, claim authorizations and entity-account grants); it stores the messages (blob `pod-batch-messages`) and shows the model their names and every risk, never their values.
- **Approval.** `approve_pod_transaction` takes `riskConfirmation` quoting every risk of every message word for word, as `sign_ixo_transaction` requires of one message.
- **`request_pod_signature`.** Sends the batch form of `sign_transaction` (chain id per network, the turn's abort signal) and reads the answer through the ixo-transaction result contract: `signed` (`txHash` for `confirm_pod_creation`), `failed` (included with a non-zero code: nothing created; code and hash kept), `rejected`, `error`, `timeout` (`outcome: 'unknown'`: the write claim stays and the same request is not sent again) or `unavailable`. With no Portal browser connected nothing is sent and the approval is kept. The old `{ blobId, unsignedTx, network }` → `{ txHash }` exchange is removed.
- **Configuration.** The POD Creator declares `IXO_TRANSACTION_CHAIN_ID_DEVNET` / `_TESTNET` / `_MAINNET` (defaults `devnet-1`, `pandora-8`, `ixo-5`) with the same schema objects as `IxoTransactionPlugin`; the env composition treats one schema object declared by two plugins as shared, so loading both logs no collision. Mainnet still needs `POD_CREATOR_ALLOW_MAINNET`.
- **Tests.** The pod-creator suites now run in the workerd pool (`pnpm test`), with a new `request-pod-signature.test.ts` over the real `FrontendCallRegistry`.
