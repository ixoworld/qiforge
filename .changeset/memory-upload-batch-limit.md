Session history uploads never send the memory engine a request it refuses. A part holds at most 50 messages counted after the conversation filter (was 200 transcript messages counted before it, so any chat past about 50 messages without a quiet period was refused whole with `422 MESSAGES_INVALID` and stayed out of memory), at most 512 KiB of body, and no message over 16 KiB (longer ones are split into marked pieces, cut with a marker past 8). The count advances after each accepted part, and every message carries a stable `uuid`, so a resend is stored once. Refusals follow the engine's error contract: a count or size rule shrinks the parts and goes on, a message the engine refuses on its own is skipped with a warning instead of blocking the session (only when other messages are accepted, so an engine that refuses everything never causes skips), `retryable: true` / 429 waits as told within a bounded budget, and anything else non-retryable stops the pass without retrying the same request. A durable per-session record lets the housekeeping alarm upload backlogs no live trigger comes for (bounded: one run of up to 3 sessions at a time, dropped after 8 attempts without progress), and the first tick after the upgrade looks once at the 5 most recent conversations, so sessions stuck before the fix recover even if the person does not write again.
