`ChatRunSummary` gains `waitingFor?: { kind: 'browser' | 'agui'; toolName: string; since: string }` (new type `ChatRunWaitingFor`), set by runtimes that park a browser tool or AG-UI action call of a chat no connected socket can take: the run waits until a browser of the session connects (opening the chat mounts `useChat`'s socket, which receives the parked call). It describes the oldest parked call, is computed per response and absent on older runtimes. New helper `isWaitingOnUser(run)`: `true` for an active run (`queued` / `running` / `recovering`) with a well-formed `waitingFor`, narrowing the run so `run.waitingFor` can be read; a malformed value counts as not waiting.

`useWebSocketEvents` is now exported (with `IWebSocketConfig`, `IUseWebSocketEventsReturn`, `WebSocketEvent` and `WebSocketConnectionStatus`) and takes `executor?: 'foreground' | 'background'` (default `'foreground'`). With `'background'` the CONNECT auth payload also carries `executor: 'background'` and `tools: Object.keys(browserTools ?? {})`, read again at every CONNECT (socket.io builds the payload on each reconnect): the runtime then sends that socket only calls of the declared tools, only while the session has no foreground socket, and none of the session's events. Changing `executor` reconnects the socket. A foreground socket's payload and credential handling are unchanged (`{ ucanDelegation, invocation? }`, stage 1 then stage 2). A background socket never involves the user: it sends the cached delegation only and never mints one — with none cached it opens nothing and reports `connectionStatus: 'error'` with an error of code `BACKGROUND_SOCKET_UNAVAILABLE` (new export) — reads its invocation with `getInvocation(oracleDid, { background: true })` at every CONNECT and never connects with a bare delegation (no invocation: the CONNECT is not sent, the socket is closed with the same error), and renews a refused CONNECT with `renewOracleAuth(oracleDid, 1, sent, { background: true })` only (never stage 2); when that renews nothing, or the next CONNECT is refused again, the socket stays disconnected with the refusal as its error. A background socket never listens for `action_call`, refuses a `browser_tool_call` of a tool its latest CONNECT did not declare with a `tool_result` error, answers calls only after the runtime's `connected` event echoed `executor: 'background'`, and on a runtime whose `connected` event lacks that echo closes without reconnecting and reports `connectionStatus: 'error'` with an error of code `BACKGROUND_EXECUTOR_UNSUPPORTED` (new export). Any socket now answers a `browser_tool_call` of its session while it has no browser tools with a `tool_result` error (`Tool <name> not found: no browser tools registered`) instead of leaving it unanswered.

`getDelegation(oracleDid, options?)` on the provider context takes `background?: boolean`: with `true` it resolves the cached delegation only (the cache's usual expiry margin applies) and never mints one, `null` when none is cached (and with `fresh` as well, leaving the cache untouched). Callers without the option keep their behaviour. The round-1 code `BACKGROUND_INVOCATION_UNAVAILABLE` is now exported from the package index as well.

`IBrowserToolParams` takes an optional `effect: 'read' | 'write'`, sent with the tool's declaration (`tools[].effect` in the message body) when set: runtimes that read it use it to decide whether a call interrupted by a restart may run again, instead of guessing from the tool's name.
