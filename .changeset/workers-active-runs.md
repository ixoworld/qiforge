`GET /runs/active` and `activeRun` on session rows. `GET /runs/active` answers `{ runs: RunSummary[] }`: every queued, running or recovering run of the chats `GET /sessions` lists, oldest first (`startedAt`, then run id), whichever client sent the message (Portal, Matrix room, channel). It follows the session list's rules: task runs (`task:<id>` sessions) are left out, and a user with a main oracle room sees only the runs of sessions in that room (a session without a row yet is placed by its stored request's room; a Portal run without one is listed). The answer comes from the coordinator's live runs with no SQL — the boot recovers every orphaned run first, and a run leaves the live map before its row is closed, so a just-stopped run never shows as running — and reads the stored rows only after a failed recovery scan. The summaries carry no `partialText` (`runSummaryOf(record, { withPartialText: false })`); the per-session route keeps it. Each `GET /sessions` row now carries `activeRun` (the same summary: the session's running or recovering run, else its oldest queued one) when the session has an active run; the key is absent otherwise, so older clients see the rows they always did.

A cold user object that has created no run since a boot that found none (`meta:runsMaybeActive` `false`) answers `{ runs: [] }` without booting. Polls spend their own `RATE_LIMIT` budget (key `<ORACLE_DID>|poll|<userDid>`, same binding), so a polling tab never pushes the user's messages into 429; clients should poll at most every ~4 s while something runs and the tab is visible, ~30 s otherwise, and not while the tab is hidden. A runtime without the route answers 404 `Run active not found` (from `GET /runs/:runId`).

`POST /messages/abort` now boots the user object before stopping (a run only the store knew after a reset is recovered and stopped instead of answering `success: false` and running on) and answers once the runs it stopped have ended, at most after the 5 s supersede grace. `RunStore.listActive()` orders ties on `started_at` by run id.
