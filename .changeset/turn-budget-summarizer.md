A turn no longer fails on its token count. The turn budget still accounts every model call (estimate reserved, settled to reported usage) and logs `[harness] turn … usage: ~N tokens (…)` and `turn_runs.usage`, but the tokens limit is gone: `TURN_MAX_TOKENS` is removed (a deployment that still sets it is unaffected), `HarnessLimitError['limit']` is `'tools' | 'time'`, and `TurnLimits` has no `tokens`. The tool-attempt cap (`TURN_MAX_TOOL_CALLS`) and the deadline (`TURN_TIMEOUT_MS`) remain the safeguards. History is now summarized by the turn's own model: the new `summarizer` model role resolves to the same model id and lane as `main` everywhere (platform default or per-request choice on OpenRouter, the Nebius main model, the user's own model and key on a BYO turn; on OpenRouter at the helper calls' `medium` reasoning effort), while `routing` stays the helper for the capability router. Summarization fires at 60% of the main model's window whatever its size (`CONTEXT_SUMMARIZE_FRACTION` default 0.5 → 0.6; never above what the summarizer reads, which only binds below a ~34.3k window) and is no longer capped by the routing model's window; `contextBudgetFor` loses its `summarizer` argument and `ContextBudget.summaryWindowTokens`, and the `[context]` line drops `(summarizer window N)`. Context windows resolve learned → `MODEL_CONTEXT_OVERRIDES` (optional) → live OpenRouter catalogue → a new built-in table (`BUILTIN_CONTEXT_WINDOWS`: a required `contextTokens` on every `MODEL_CATALOG` entry plus the role-map, Nebius and BYO model ids; origin `builtin`) → the 100k default only for a model nobody knows.
