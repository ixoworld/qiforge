# Request admission

Workers plugins can implement `getRequestAdmission(context)` to handle a bounded authenticated read before model selection, attachment interpretation, capability routing, agent construction, and summarization. The context contains a redacted configuration, verified user and session identity (including the Matrix `roomKind`, `eventId` and `threadId` when present), the message, optional bounded metadata, and a cancellation signal. It exposes no model or mutation tools.

The configuration a handler sees is not the merged env: it holds the core settings without credentials (`OPEN_ROUTER_API_KEY`, `MATRIX_ORACLE_ADMIN_PASSWORD`, `MATRIX_RECOVERY_PHRASE` and `CLOUDFLARE_API_TOKEN` are removed) plus the keys the handler's own plugin declares in its `configSchema`. Keys owned by other plugins are left out. A plugin's own keys are passed through, secrets included, because the handler must reach the same authorized service as the plugin's read tool.

Return `{ kind: 'pass' }` for unsupported requests or `{ kind: 'handled', text, title }` for a deterministic authorized read. The first handler in plugin dependency order wins. Each handler has `REQUEST_ADMISSION_TIMEOUT_MS` (default 2000 ms) to answer; when the limit passes its signal is aborted, a warning is logged, and the handler counts as `pass`, so the turn goes on to the next handler or the agent. Authorization and read failures throw and fail the turn; they do not fall through to an agent. A handler must use the same authorized service as its ordinary read tool and must never execute mutation handlers or invoke inference through captured dependencies.

The host offers a turn to admission handlers only when it has no attachments, is not a scheduled task run (`taskRunId` set or a `task:` session), and does not come from a Matrix group room. A direct reply is posted into the room the turn came from, so in a group room one user's authorized read would be shown to every member. Handlers still receive `roomKind` and must refuse (`pass`) anything they would not show to everyone in the room.

A refused or failed admission (a handler throws, or returns an empty or oversized answer) ends the run as `failed` with the same terminal frames as a failed agent turn: `run` (fresh runs), an `error` frame with `kind: 'request_admission'`, `source: 'platform'`, `retryable: true` and a generic message, then `done` with `failed: true`. The handler's own message is written to the log only; the run row stores `request admission failed`. A user abort or a superseding message during admission ends the run as `aborted` with `done` carrying `aborted: true`. In all three cases the user's message is not written to the transcript and no model is called.

The host persists an `admitting`, `agent`, or `direct-read` disposition on the durable run. Recovery repeats interrupted read admission, replays an already recorded direct result, or resumes an ordinary agent. An attempt that recovers from `admitting` never reached the agent, so when admission then passes, the agent runs with the turn's input (message and attachments) instead of continuing from the checkpoint. Historical runs without a disposition resume the agent. The client cannot set a disposition. Direct replies append stable message IDs to the normal transcript, use the existing SSE buffer and Matrix mirror, and select a deterministic title. They skip agent preparation and after-turn shadow comparison. Group compaction runs independently and is not attributed as a generative call of this request.

"Inference-free" covers the request itself: a direct read skips `prepareTurn` (model and BYO resolution, attachment interpretation, capability routing, the agent build), the turn budgets, summarization, title generation (the handler's `title` is used) and LangSmith tracing. It does not make the turn invisible to the rest of the runtime. `afterTurn` still runs `touchSession`, marks the database dirty for the owner copy, and the memory indexer later indexes the session transcript, direct-read messages included, on its own schedule and not as part of the turn. An abort that arrives after the direct-read messages were appended ends the run as `aborted`; the reply stays in the transcript, but the session is not touched, no title is set and the reply is not mirrored to the room.

`getRequestMiddlewares(ctx)` contributes request-local LangChain middleware to ordinary agent turns. These extensions receive the full RuntimeContext and are collected afresh after boot middleware. They do not provide inference avoidance; use admission for that boundary. Plugins must not retain either context on singleton instances.

New flow conditions require `source` equal to `configured_input` or `runtime_output`. A stored condition without a source is read as `runtime_output`, the runner's interpretation of an untagged condition, so a read step is valid `update_step` input; the stored block is not rewritten until the step's conditions are edited. `update_step` clears a semantic gate with `semanticGate: null`; omitting the field keeps it. A separate `semanticGate` contains version 1, decision `flow.gate.semantic`, criterion, rubric, and named input fields. It is an additional host gate, never a replacement for deterministic conditions or authorization. Runner support and per-definition activation are host responsibilities.

`readFlowDecisionContext(ctx, ref?)` returns the authenticated `FlowSpecRead` snapshot, including its resolved `ref`, through the existing Matrix room-membership guard. It does not invoke inference or mutate the flow. Hosts must select and redact the fields needed for their Decision variables rather than trust model-supplied draft state. Input, condition, and semantic-gate edits update both the editor blocks and compiled `qi.flow.nodes` consumed by the runner.

Decision calls combine caller cancellation with turn cancellation. Already cancelled calls do not reach the provider, cancellation rejects even if a provider ignores the signal, and a result arriving after cancellation cannot become an accepted answer.
