# Matrix Usage Inventory (active codebase)

Survey date: 2026-08-24. Scope: `packages/matrix`, `packages/oracle-runtime`,
`packages/oracles-client-sdk`, `packages/oracles-chain-client`, `packages/common`,
`packages/events`, `apps/qiforge-example`. `apps/app` (legacy, being removed)
has its own parallel, older Matrix wiring and was excluded. `packages/events`
has no Matrix references.

Note: the survey ran while the VFS checkpoint store was being written; the
`'vfs'` implementation (`matrix/checkpointer/vfs-checkpoint-store.ts`) now
exists — see `specs/checkpoint-vfs-backup.md`.

Legend — **boot-hard**: the app cannot start (env validation) or a core
singleton is initialized unconditionally at boot; **per-feature**: only
exercised when that plugin/code path is active.

## 7. Env vars (`packages/oracle-runtime/src/config/base-env-schema.ts`)

All eight are Tier-0 (required; validation throws at boot):

| Var                                | Gates                                                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `MATRIX_BASE_URL`                  | Homeserver URL for every client construction.                                                                |
| `MATRIX_RECOVERY_PHRASE`           | SSSS phrase; E2E key-backup restore at boot (best-effort).                                                   |
| `MATRIX_STORE_PATH`                | Local path for bot-sdk storage + Rust crypto store.                                                          |
| `MATRIX_ORACLE_ADMIN_USER_ID`      | Oracle bot's user id; also `@mention` detection in group rooms.                                              |
| `MATRIX_ORACLE_ADMIN_PASSWORD`     | Bot password (login/ops tooling).                                                                            |
| `MATRIX_ORACLE_ADMIN_ACCESS_TOKEN` | Access token for `MatrixManager`, `MatrixStateManager`, `EditorMatrixClient`, and the raw key-setup fetches. |
| `MATRIX_ACCOUNT_ROOM_ID`           | Oracle's private account room (signing mnemonic + encryption key).                                           |
| `MATRIX_VALUE_PIN`                 | PIN encrypting the mnemonic/key in the account room.                                                         |

Also read directly via `process.env`: `MATRIX_HOMESERVER_NAME` (alias resolution
override), `MATRIX_CP_CACHE_TTL_MS` / `MATRIX_CP_CACHE_MAX` /
`MATRIX_CP_MAX_SIZE_BYTES` (tuning for the unused legacy saver).

## If Matrix were removed — blast radius, highest first

1. **Session/thread identity.** Session ids _are_ Matrix event ids (`SessionManagerService.createSession`); the listener bridge resolves sessions by walking `m.relates_to`. A new session/thread-id primitive would have to thread through `SessionManagerService`, `MatrixListenerBridge`, `MessagesService`, `PostMessageSyncer`.
2. **Checkpoint durability.** Matrix media is the only durable store for per-user conversation state until the VFS store (this branch) reaches full coverage.
3. **Oracle signing identity + secrets key.** Provisioned in and read from the Matrix account room at every boot — UCAN minting and secret decryption have no other key source.
4. **User UCAN delegations + user secrets.** Room state / encrypted timeline events.
5. **Plugin-scoped durable state** — user preferences, oracle-payments engagement + pending-claims index, group-chat channel memory. Each is SQLite/KV-shaped and independently swappable.
6. **Chat ingress channel** — the richest UX surface (threads, typing, live cards, attachments); portal (HTTP/SSE) and Slack already exist as independent ingress.
7. **Editor documents** — stored _as_ Matrix CRDT event streams (`@ixo/matrix-crdt`); a genuine migration.
8. **Voice/video** — Matrix as identity proof + signaling for LiveKit; swappable for direct auth.
9. **Task rooms** — delivery/approval channel; redirectable.
10. **Audit log** — `ixo.action.log`; any sink.
11. **E2E crypto / cross-signing** — only protects Matrix content; self-resolving.

Already decoupled: `/health` endpoints, `packages/events`, and the plugins listed as having no Matrix usage.
